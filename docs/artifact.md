# SliceGPT artifact v1

ECPA manifest version describes plugin packaging. `slicegpt-artifact/1` describes
model files; the two versions are independent.

A v1 directory contains `config.json`, exactly one `model.safetensors`, and the
base tokenizer files. Sharded, quantized, tied-embedding, sliding-window, and
unknown architecture artifacts are not accepted by v1.

The config uses `model_type=llama` or `qwen2` and the explicit
`SliceGPTLlamaForCausalLM` or `SliceGPTQwen2ForCausalLM` architecture. There is no
`auto_map`: Transformers supplies the config class, while vLLM uses the plugin
model. Loading the weights into a dense Transformers model is not supported.

`slicing_config` contains embedding/final widths, unchanged attention head
dimension and four complete arrays of per-layer attention/MLP input/output
widths. `slicegpt_artifact` contains:

- `schema_version`: exactly `slicegpt-artifact/1`;
- `producer`: package name, version, and `legacy_source_commit` identifying the
  extraction baseline (not a claim that the produced wheel equals legacy code);
- `base_model`: model id, immutable revision, and model license identifier/URL;
- `original_hidden_size`: the RMS normalization divisor before slicing;
- `calibration`: supplied calibration record, or explicit `not-recorded`;
- `weights`: SHA-256 of `model.safetensors`.

Archive the wheel hash and repository commit with each experiment to identify
the exact converter, in addition to the package version. Calibration records
generated by `slicegpt-compress` include dataset revision/license/fingerprint,
seed, sample count, sequence length, dtype and slicing parameters. Model and
dataset permissions remain those of their respective sources; this repository
does not relicense them or bundle their data.

Validation rejects malformed/non-integral dimensions, disconnected residuals,
invalid GQA/head dimensions, absent/extra tensor names, wrong shortcut shapes,
unsupported dtype, unknown schema, and checksum mismatches. The directory CLI
checks the full weight digest and safetensors headers without loading torch.
Runtime initialization validates the config; streaming weight loading validates
tensor names, duplicates, completeness and shapes before packing QKV/MLP weights.
The runtime stream does not rehash the file: run directory validation before
serving. Checksums provide integrity checking, not signatures or authenticity.

Legacy migration accepts only known SliceGPT architectures/types and a single
safetensors file. It removes the old config `auto_map`, retains weight bytes,
and writes a new destination atomically. Failed migration leaves the source
untouched and publishes no destination. Unknown existing artifact schemas are
not downgraded or relabeled.
